도안(圖案)은 물건을 만드는 바탕이 되는 그림입니다. 제품의 화면 하나하나를 짧은 텍스트 파일로 둡니다. 화면에 무엇이 있는지, 비었을 때·불러올 때·에러일 때 어떻게 보이는지, 버튼을 누르면 어디로 가는지, 어느 기획서에서 나왔는지. 이 파일은 AI 에이전트가 쓰고, 사람은 브라우저에서 요소를 가리키며 "이 열 빼 줘"처럼 말로 고칩니다. 에이전트는 새 판을 제안만 하고, 적용은 사람이 누릅니다. 제품 화면에서 피그마를 대신하는 게 목표입니다. 웹, 앱, 키오스크 모두요.

풀려는 문제는 디자인 파일이 여러 사람과 에이전트, 몇 달의 이력을 거치며 깨지는 지점들입니다. 아무도 안 그린 화면, 아무도 안 정한 값, 코드와 어긋난 디자인, 몰래 고치는 에이전트. 그래서 상태는 화면 전체를 반복하지 않고 달라진 부분만 적고, 정하지 않은 값은 담당자가 붙은 `$tbd`로 남깁니다. 검사 열다섯 개가 빠진 상태나 미정 값을 파일과 줄 번호로 짚고, 정리되지 않으면 main에 들어가지 못합니다.

뷰어에서는 화면을 섹션별로 훑고, 상태를 탭으로 넘기거나 나란히 비교합니다. 요소를 누르면 어느 파일 몇 줄에서 왔는지 보이고, 거기에 코멘트를 남깁니다. 에이전트의 제안은 상태마다 지금 화면 옆에 새 화면을 나란히 그린 페이지로 오고, 이름을 적고 적용하거나 반려합니다.

이미 피그마에 그린 팀은 `import figma`로 가져옵니다. 컴포넌트 이름을 먼저 짝지어 두면 풀리지 않은 값이 468개에서 80개로 줄고, 남은 것은 첫 검사의 할 일 목록이 됩니다. 화면마다 iOS·Android·태블릿·키오스크·웹을 정하면 그 기기 폭과 프레임으로 그리고, antd·MUI나 팀의 컴포넌트로 그릴 수도 있습니다.

`npx @junyoung735/doan`으로 설치 없이 쓰고, Claude Code·Cursor·Codex에 MCP로 붙입니다. 검수 규칙은 [fig](/play/fig-pm/)에서 가져왔습니다.
